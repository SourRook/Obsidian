## Waveguard Cap Channel Ordering (CA-213)

- Investigated why the CA-213 topoplot was scrambled. Root cause: the eego SDK has no concept of cap/montage — `OpenEegStream(rate)` only takes a sampling rate. The SDK returns hardware-pin-indexed columns, not electrode-labelled channels.
- The NA-271 net and CA-213 cap have zero overlap in their pin-to-electrode mappings — all 128 pins map to different electrodes.
- Built `eeg_april_test.py` as a flat, modular debugging script: load → extract coords → bandpass 12–20 Hz → average re-ref → downsample → FOOOF spectrum → topoplot video. Each step is its own function, each prints one line.
- Fixed the channel ordering by adding a `use_txt_locs` toggle that relabels .bin columns using the `CA-213_channels.txt` pin order before matching against the `.elc` file. This resolved the scrambled topoplots.
- Output folder now auto-derives the `rec_*` ID from the meta path.
